# Git 取数方法

在用户指定仓库或当前 Git 仓库读取本地提交。确定本期项目与仓库的对应关系。默认范围为当前 `HEAD` 可达的提交，指定分支、标签或仓库时按指定范围读取，多个仓库分别汇总。对跨分支重复的 SHA 或同一变更只计一次。需要远端记录时，依据用户指定的来源和可用权限取得。

使用 `scripts/git_evidence.py` 批量提取提交标题、正文、作者和日期。脚本依赖 Python 3.9 或更新版本和支持 `--since-as-filter` 的 Git，从当前 Skill 目录引用脚本并传入用户仓库路径。

```powershell
python "<Skill 目录>\scripts\git_evidence.py" --repo "<仓库路径>" --ref HEAD --start 2026-10-01 --end-before 2026-11-01 --offset=+08:00
```

`--start` 当天零点计入，`--end-before` 当天零点截止，`--offset` 采用汇报所在地的 UTC 偏移。默认按提交者时间筛选，与作者日期可能不同。按作者日期或发布时点统计时，依据该口径另取记录。只读脚本输出 UTF-8 JSON，包含引用、起止时刻、可见提交和浅克隆标记。工具输出过长时将结果暂存到本地分段查看。没有可用 Python 或 Git 版本不支持脚本参数时，可用只读 `git log` 读取相关引用的 `%H`、`%cI`、`%aI`、`%s`、`%b`，再按同一时区和边界筛选。

- 对「优化」「修复」等笼统标题，先核对提交涉及的模块、文件和测试，再挑有业务影响的相关差异。可用 `git show --stat --no-ext-diff <SHA> --` 查找路径，再用 `git show --no-ext-diff --no-textconv <SHA> -- <路径>` 查验。可根据目录、接口、页面、测试和配置准确命名工作事项。
- 合并、回退或重新提交可能改变期末状态。合并提交可与其第一父提交比较，并与子提交去重。某项改动本期又被回退时按期末状态表述，后续恢复以记录为准。
- 在汇报口径中简记所覆盖的仓库及引用。发现浅克隆、分支缺失或未包含指定仓库时按可见范围整理。期内无可见提交时，可继续用日报或群聊形成汇报，并说明所查范围。
